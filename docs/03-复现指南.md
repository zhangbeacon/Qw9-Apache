## 1. 先读这个警告

**现在不是克隆即跑的便携工程。** 保留正式目录是为了不进一步破坏依赖，不表示绝对路径问题已解决。

现有验证脚本硬编码以下基址，不会随当前目录自动定位：

```text
/mnt/e/强网拟态/cve/apache       配置、PoC、采证位置
/mnt/e/强网拟态/cve/_downloads   源码包缓存
/root/work/apache               2.4.49 构建树
/root/work/miner/src             2.4.50 及静态定位所需其它版本源码
/opt/httpd /opt/httpd-asan        漏洞版安装树
/opt/httpd-2450                  2.4.50 差分安装树
```

**从发布副本或新克隆目录执行脚本，仍可能读取并覆盖原工作区的证据、配置，甚至操作原实验进程。** 新共创者应先只读代码；准备独立、隔离环境并确认所有路径、权限和端口后再运行。路径参数化是下一步工程任务，不是在本轮整理中偷偷完成的改造。

本次仅检查目录依赖、内容完整性和文档，没有执行 PoC、构建或安装依赖。

## 2. 现在保留什么

```text
cve/apache/
├── build/       7 个正式构建、环境与分组入口
├── conf/        原有 13 个配置 + 1 个 Lua 入口
├── poc/         11 个规范 verify、4 组负向对照及其辅助代码

```

正式配置与 PoC 保持上次发布字节不变；没有为了美化目录批量替换脚本路径。旧诊断、探测、临时试验、构建日志和完整原始报文统一进入[完整历史快照](../archive/README.md)。

## 3. 原环境需要哪些前提

| 类别 | 原实验前提 | 本仓库是否提供 |
|---|---|---|
| Linux | Windows + WSL1 Ubuntu-CTF / Ubuntu 22.04，原脚本常需 root 权限 | 不提供系统镜像 |
| 构建 | gcc/make、APR/APR-util、PCRE、Lua 等；[依赖脚本](../cve/apache/build/install_deps.sh)仅负责其中一部分 | 提供脚本，不自动执行 |
| 原始源码 | httpd 2.4.49 压缩包及指定源码树 | 不提供下载缓存 |
| 漏洞版安装 | 普通和 ASAN 构建、安装树中的模块、mime.types 等 | 提供[构建脚本](../cve/apache/build/build.sh)，不提供二进制 |
| 补充源码 | 2.4.50 差分树；23943 静态定位所需 2.4.49/2.4.53 文件 | 不提供；原下载脚本在归档中 |
| 负向对照 | /usr/sbin/apache2 与 /usr/lib/apache2/modules，原记录为 Ubuntu 2.4.52-1ubuntu4.25 | 不提供系统软件包 |
| 运行工具 | Python3、curl、Valgrind、进程/端口检查工具等 | 需要自行确认，依赖脚本不包办全部 |

2.4.49 源码上游为 [Apache 官方归档](https://archive.apache.org/dist/httpd/httpd-2.4.49.tar.gz)，已有记录的 SHA256 为：

```text
345d3b9b218b1974d1cebd5ae72f6a661d83b52d839310222ff9ec94abb62205
```

原配置故意开放危险行为用于实验，不能直接作为生产配置。端口涉及 8082、8090–8096 等，须逐脚本确认；部分入口会清理匹配的 httpd 进程。

## 4. 正式入口怎么找

### 构建与环境

- [环境检查](../cve/apache/build/check_env.sh)：查看原环境情况，不等于自动准备所有依赖。
- [安装构建依赖](../cve/apache/build/install_deps.sh)：会修改系统，先审阅再执行。
- [2.4.49 构建](../cve/apache/build/build.sh)：支持 normal / asan，要求源码包已就位。
- [2.4.50 构建](../cve/apache/build/build_2450.sh)：要求预先存在指定 miner 源码树，不负责下载。

下列命令**仅示意已准备好的原隔离环境中的用法**，不是新克隆目录的快速启动命令：

```bash
ROOT=/mnt/e/强网拟态/cve/apache
bash "$ROOT/build/build.sh" normal
bash "$ROOT/build/build.sh" asan
```

### 按 CVE 验证

每个规范入口、报告与历史摘要均集中在[漏洞矩阵](02-漏洞矩阵.md)。规范路径是：

```text
cve/apache/poc/<CVE>/verify.sh
```

一般以退出码 0 表示该入口的机器断言命中；23943 的资源受限入口返回 3，不能将其当成功。必须结合本轮日志和具体判据，而不是只看到命令结束就记 PASS。

### 现有批量入口的真实覆盖

| 入口 | 实际内容 | 退出码局限 |
|---|---|---|
| [最初三项分组](../cve/apache/build/run_all_verify.sh) | 41773 / 44224 / 44790 + 对应负向组 | 打印单项退出码，没有可靠聚合全组失败 |
| [A 组](../cve/apache/build/run_all_A.sh) | 25690 / 22720 / 42013 + 对应负向组 | 有分组汇总，不代表全 11 项 |
| [补充检查组](../cve/apache/build/run_my_verifies.sh) | 38474 / 22719 / 23943，打印日志和进程 | 主要供观察，没有可靠聚合全组失败 |

**没有现成的 11 项全量可靠 runner。** 响应侧两项及其它项目应按矩阵的逐项入口操作；统一调度和正确退出码汇总仍待实施。

### 修复版与差分

- 四个修复版入口的覆盖范围见[负向对照表](02-漏洞矩阵.md#3-修复版负向对照)；固定目录没有统一的 verify.sh。
- [2.4.50 差分验证](../cve/apache/poc/CVE-2021-42013/verify_2450_matrix.sh)依赖独立安装树和源码元信息，不会自动调用 2.4.50 构建。
- 负向入口有的假定 CVE 证据父目录已存在，本分支保留的各项判定摘要也维持这些目录。不要只复制单个负向脚本就假定可跑。

## 5. 完整证据和旧工具怎么找

- 在线快速核查：矩阵链接到现役的 11 份历史判定摘要和报告。
- 完整核查：原始访问/错误日志、响应报文、构建日志及全部 fuzz 样本均在[归档说明](../archive/README.md)所列的固定提交与 ZIP 中。
- 复查旧补充取证或资料生成：从快照独立解包后阅读，不把旧过程工具重新铺回主线。

11 份报告中原有的证据代码路径仍对应原实验布局；归档按原路径完整保留。摘要不是完整原始证据，旧 PASS 也不能充当未来新一轮结果。
