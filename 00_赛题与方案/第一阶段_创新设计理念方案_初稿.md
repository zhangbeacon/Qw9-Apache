## 0. 摘要

同构部署使同一缺陷在多台服务器上被同一攻击重复命中。本作品以 Apache httpd 2.4.49 为基准程序 V1，构建一条**自动化异构变体生成与验证流水线**：生成两个功能等价、内部实现与运行形态不同的变体 V2/V3，并用同一套触发脚本在 V1/V2/V3 上对比 6 个独立根因漏洞的攻击表现。

本方案的两项核心创新：

1. **LLM 监管 Agent（自动化编排创新）**：流水线引入常驻 LLM 监管智能体，形成"执行层（确定性脚本）—监管层（LLM 诊断与处置）—裁决层（机器判定门）"三层架构，对构建失败、资源异常与证据完整性实时诊断处置，全程决策留痕可审计；
2. **可复现性熵（量化建模创新）**：定义漏洞可复现性熵 H(i)∈[0,1]，把"EXP 在不同内部结构扰动下能否稳定复现"变成可计算、可对比、可排序的数值指标，用以量化**软件多样性带来的安全增益**，并对比不同漏洞类型的熵分布、给出模型。

**当前实测基础**：11 个 CVE 中 10 个已在 2.4.49 未修复版复现成功（1 个静态定位），覆盖 7 类 CWE；Ubuntu 2.4.52 修复版负向对照全部通过；自建 pristine 2.4.50 完成 42013 版本差分；全部测试可一键复跑。

## 1. 题目理解与目标

### 1.1 赛题核心问题

三个版本不能只是文件名或哈希不同——必须存在**影响攻击过程的安全相关差异**，且该差异可被主办方复核。赛题对"差异"的定义原文即要求到**利用原语粒度**（"攻击利用的原语、控制流结果、信息泄露程度或最终攻击目标不同"），这决定了本作品的证据体系必须做到原语级量化。

### 1.2 目标

1. V1 选型钉定在漏洞密度最高的历史版本（已完成：2.4.49）；
2. 自动化流水线生成 V2/V3（第二阶段实施）；
3. 对 6 个独立根因漏洞跑同一触发脚本，产出三态差异矩阵；
4. 以可复现性熵量化多样性的安全增益，输出可复核的量化模型（创新点二）。

### 1.3 三态判定基准

| 判定 | 定义 |
|---|---|
| 触发 | 攻击目标达成（泄露字节/Cookie 注入/命令执行/异常响应） |
| 静默 | 缺陷代码仍执行，但无可观察影响（如越界落入 malloc slack） |
| 形态改变 | 同一缺陷在不同变体上表现为不同信号/不同响应码/不同泄露量 |

## 2. 基准程序选择与威胁模型

### 2.1 选型方法与结果

选型经三重独立验证：① 三份独立选型报告交叉筛选（各推第一名：nginx / dnsmasq / Apache）；② 三个"第一名"软件全部完成复现实测（共 10 个 CVE，9 个成功）后按证据强度终选；③ 三个 AI 评审模型独立审计并两轮表决（3:0）。

**终选结果：Apache httpd 2.4.49。** 决定性理由：

- CVE-2021-41773 是候选池中唯一**不依赖 sanitizer、单条 HTTP 请求即可实测**的 RCE（远程、在野利用、CISA KEV 收录）；
- 逻辑型漏洞占优，V1/V2/V3 差异可直接呈现在 HTTP 状态码/响应层（200 vs 400/500/崩溃），满足赛题"差异不能只是哈希/地址不同"的要求；
- 模块体系（proxy/rewrite/lua/sed/cgi）提供丰富的可配置攻击面，便于构造多样化测试例。

落选说明（有实测依据）：nginx 两条内存缺陷仅 ASAN 可见，差分观察面窄；dnsmasq 两条核心漏洞仅 ASAN 可见且 13704 需重钉 2.77 版本，答辩口径风险大。

### 2.2 V1 与漏洞池

- 源码：`httpd-2.4.49.tar.gz`（sha256 `345d3b9b…2205`，archive.apache.org）；
- 漏洞池：11 个 CVE（10 个动态复现成功 + 1 个静态定位），覆盖 **CWE-22 / 444 / 787 / 476(918) / 116 / 113 / 665** 七类；
- 完整清单见《CVE总览-Apache.md》；每个 CVE 均有 `poc/<CVE>/verify.sh` 机器判定脚本与原始证据目录。

### 2.3 威胁模型与实验边界

攻击者可向 HTTP 端口提交受控请求（含路径、头、body、代理 URI），目标为文件泄露/命令执行/请求走私/SSRF/DoS。所有测试在本机隔离 WSL 环境完成，载荷无害化（`id`/`uname`、标记字符串）。运行配置差异（如 `Require all granted`、`ProxyRequests On`、mod_lua 启用）作为**变体组成部分**如实记录，不冒充编译差异。

## 3. 系统设计

### 3.1 流水线架构

```text
V1 源码 + 变体规格(variants.yaml) + 策略配置
        ↓
  ① 构建编排（编译器×优化×分配器×加固×配置收敛）
        ↓
  ② 功能一致性测试（正常流量 golden diff，不通过即淘汰）
        ↓
  ③ 互补性筛选（校准集攻击抑制率最大化）
        ↓
  ④ 固定 V2/V3，生成构建溯源清单（sha256+参数+种子）
        ↓
  ⑤ 漏洞矩阵：6 CVE × V1/V2/V3 同触发脚本
        ↓
  ⑥ 三态判定 + 可复现性熵 + 差异矩阵输出
        ↺ 全程：LLM 监管 Agent 值守（失败诊断 · 资源看门狗 · 证据完整性审计，见 3.3）
```

编排伪代码（示意）：

```text
for spec in variants_yaml:            # ① 变体规格展开
    artifact = build(V1_src, spec)
    if not functional_test(artifact): # ② 功能一致性
        drop(spec); continue
    score = calibration_attack(artifact, calib_set)   # ③ 校准集抑制率
candidates = top_pair_by_min_joint_success()
V2, V3 = candidates                   # ④ 固定变体对
for cve in holdout_set + calib_set:   # ⑤⑥ 全量矩阵
    run(cve, V1); run(cve, V2); run(cve, V3)
compute_entropy(matrix)               # 可复现性熵（3.4）
emit(fingerprint_cards()); emit(matrix())
```

### 3.2 变体构造策略（设计依据：11 CVE 敏感性实测）

对 11 个 CVE 的挖掘与复现表明，漏洞对异构手段的敏感性呈两极：

| 漏洞类型 | 实例 | 对编译器/分配器 | 对源码级等价重构 | 对配置收敛 |
|---|---|---|---|---|
| 逻辑型（路径穿越/走私/SSRF） | 41773、44224、22720、25690 | **不敏感**（换 gcc/clang 仍命中） | **敏感**（规范化重写即失效） | 敏感（关代理/收紧授权即失效） |
| 内存型（越界写/下溢/未初始化） | 44790、23017、14491 | **敏感**（堆布局漂移 → 崩溃/静默/泄露三态） | 部分敏感 | 不适用 |

**变体构造规则**：V2 采用**加固型编译栈**（clang + FORTIFY + 分配器替换），针对内存型漏洞制造"崩溃 vs 静默"漂移；V3 采用**语义等价重构 + 攻击面收敛**（路径规范化等价实现、代理/CGI 配置最小化），针对逻辑型漏洞使触发失效。V1 为原始基线。该策略是 11 个 CVE 实测数据的直接推论，不是经验假设。

### 3.3 创新点一：LLM 监管 Agent——执行/监管/裁决三层分离

自动化流水线的痛点不是"没脚本"，而是**脚本失败时没人管**：构建报错、资源超限、证据文件异常、多任务抢端口——这些恰是评审现场最容易翻车的环节。本设计在流水线中引入常驻 **LLM 监管 Agent**，形成"执行层（确定性脚本）—监管层（LLM 诊断与处置）—裁决层（机器判定门）"三层架构。

**监管 Agent 的五项值守职责（均有实测依据）**：

| 阶段 | 职责 | 实测案例（本队真实发生过） |
|---|---|---|
| 构建期 | 读编译错误定位原因（缺依赖/新编译器不兼容旧代码），自动装依赖或打兼容补丁后重试 | nginx 1.13.2 在 gcc 11 下 `current_salt` 报错，靠兼容补丁解决 |
| 变换审查期 | 源码级等价重构 diff 的合理性预审（是否偷改语义/顺手修洞/引入新行为），可疑 hunk 转差分测试 | 44224 审计中识别出"任意 UDS"超出公告范围 |
| 测试期 | 功能一致性失败分类（崩溃/输出差异/配置错），决定重试、调参或淘汰 | fuzz 首版未命中，读源码修正生成结构后命中 |
| 资源期 | 看门狗：构建超时、内存峰值（23943 >2GiB 评估）、日志撑盘、端口/进程冲突仲裁 | 实测发生双 fuzzer 抢端口、日志爆盘，看门狗自动止损 |
| 采证期 | 证据完整性审计：PASS 必须来自本轮新鲜输出，负向对照必须已执行，不符即打回 | 抓到并修复"脚本用旧文件误判 PASS"事故 |

**三条铁律（防幻觉设计）**：

1. 监管 Agent 只有**处置建议权**，没有**判定权**——漏洞命中与否、变体是否等价，永远由机器判定门（退出码/回放验证/负向对照）说了算；
2. 每个决定写入 `journal.jsonl` 决策日志（时间、依据、动作、回滚点），全程可审计；
3. 任何修改先存快照，改砸可回滚。

**实现要点**：事件监听循环（构建/测试/采证的失败与异常事件）→ LLM 诊断（可用本机 GPUStack 模型，成本≈0）→ 工具调用执行处置；判定类事件不走 LLM，直接机器判定。

### 3.4 创新点二：可复现性熵——多样性别安全增益的量化建模

#### 定义

对漏洞 i，取 V1 的变体集合 V={v₁…v_K}（同一源码、不同内部结构扰动；**运行配置恒定**，避免测成配置敏感性），漏洞 i 的攻击脚本在每个变体上独立重复 m 次，结果按三态分类（触发/静默/形态改变），记各类频率 π₁,π₂,π₃：

**H(i) = − Σ πⱼ · log₂ πⱼ / log₂ 3 ∈ [0,1]**

- **H→0（低熵）**：跨变体确定性行为——EXP 对内部结构扰动不敏感，多样性防御对该漏洞天然无效；
- **H→1（高熵）**：行为完全由内部结构扰动决定——多样性**天然抑制**稳定利用，即拟态防御的安全增益所在。

因此**熵本身就是"多样性别安全增益"的度量**：它把赛题标题里"安全增益验证"四个字变成可计算、可对比、可排序的数值指标，并可对比不同漏洞类型（越界写/下溢/逻辑型）的熵分布、给出模型。

#### 实验设计（第二阶段）

1. 构建变体集：编译器{gcc,clang} × 优化{O0,O2} × 分配器{ptmalloc,jemalloc} × 加固{±FORTIFY} 的子集，**K=8~12 个**；
2. 触发实验：6 个计分 PoC × K 变体 × m=5 次（自动编排器产出，约 360 次触发实验）；
3. 计算每个 CVE 的三态分布与熵，出两张图：六漏洞熵对比条形图、熵 vs CWE 类型分布图；
4. 报告置信区间（K、m 有限，熵估计有偏差，如实标注）。

#### 已有实测对预期熵的支撑

| 类别 | 预期熵 | 已有实测依据 |
|---|---|---|
| 逻辑型（41773/44224/22720/25690） | **低** | 换 gcc/clang 仍 200+passwd/走私成功——确定性触发 |
| 边界敏感型（44790） | **中高** | distance≤7 必崩、≥8 全静默；ASAN 下崩、普通下静默——结果分布随构建方式漂移 |
| 隙落型（23017/14491） | **高** | 1 字节写落 malloc slack 即静默，堆布局微变即崩——同输入跨变体三态 |

> 注意：可复现性熵实验依赖 V2/V3 构建完成（第二阶段）；本阶段先以 V1 的构建方式差分（plain/ASAN）与修复版对照给出试算示例。

#### 与评分的对接

- **量化建模**直接支撑"量化安全增益"要求；
- 熵分布对比图 = "漏洞与攻击类型丰富度"的量化证据；
- "熵高 = 拟态防御难点、熵低 = 多样性天然有效"是答辩的点题句。

### 3.5 校准/留出划分

6 个计分 CVE 按根因分为校准集（41773/44790/22720）与留出集（44224/38474/25690）：变体配对与熵实验只依据校准集选择，留出集仅做最终验证——避免选择过程过拟合，这是多数仅有 3 个漏洞的队伍无法实施的验证纪律。

## 5. 泛化与迁移

- 流水线以 `variants.yaml` 声明变体规格，与具体程序解耦；同一 verify 契约已在 **nginx 1.13.2 / dnsmasq 2.77 / Apache 2.4.49 三个异构软件**上实测跑通（各 3 CVE），是泛化能力的直接证据；
- 迁移验证模板：新基准程序只需提供（源码 URL、构建命令、触发脚本、判定断言）四项即可接入。

## 6. 量化评估方案

- **安全增益**：双变体共同攻击成功比例、**可复现性熵 H(i)**（3.4 节）、跨变体迁移成功率（分校准/留出统计）；
- **开销**：构建时间、内存峰值（RSS）、请求延迟 P50/P99、功能一致性 diff；
- **可复现性**：全量 manifest（源码 sha256、工具版本、编译参数、随机种子）、一键复跑、结论漂移 diff；监管 Agent 决策日志 `journal.jsonl` 全程留痕。
