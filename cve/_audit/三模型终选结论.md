## 共识理由（三家交叉认可）

1. **41773 是全场唯一不依赖 ASAN、单请求可实测的 RCE**：curl 直读 `/etc/passwd` + `uid=0(root)`，基础漏洞验证 6 分里最稳的一格，答辩演示冲击力最强。
2. **差分观察面最好**：三条均为逻辑型漏洞，V1/V2/V3 差异落在 HTTP 状态码/响应层（200 vs 400/500/崩溃），天然满足"差异不能只是哈希/地址不同"；反观 nginx 23017 与 dnsmasq 14491/14496 非 ASAN 下三变体全静默，差分观察面塌缩。
3. **修复版负向对照是新鲜证据**：同一组 PoC 在 2.4.52 上三合一 `NEGATIVE CONTROL PASS`（41773→400、44224→500、44790→200），直接支撑"迁移/抑制 7 分"的论证骨架；CWE 覆盖 22/476(918)/787 三类根因、去重清晰。

## 三家共同标注的最大风险（下一步必须补）

> **V1/V2/V3 变体尚未实际构建，也未用同一 PoC 跑出三态日志——"迁移抑制 7 分"目前是骨架已备、实证未补。**

配套动作：
- 答辩前必须产出 V1/V2/V3 实际构建 + 同一 PoC 的三态结果矩阵；
- 注意"直接拿 2.4.50/2.4.52 当 V2/V3"属于"修复式异构"，赛题明说可用但泛化/实用分会受限——更稳的路线是编译器×优化×分配器×加固参数的流水线变体（总报告 §7 已给逐 CVE 差分预期）；
- 如实申报配置前提：41773 需 `Require all granted`、44224 需 `ProxyRequests On`、44790 需 mod_lua；44224 以声明 UDS（变体 A）为主判据、44790 只主张 DoS。

## 落选理由（一句话版）

- **nginx 1.13.2**：7529 判定最稳，但 23017 纯 ASAN、41741/42 只兑现越界读，非 ASAN 差分面窄，且三条修复对照是旧证据未复跑。（作为备选：若 Apache 构建环境出问题，按三方排序它是第一替补。）
- **dnsmasq 2.77**：两条 ASAN-only + 14496 需 `--add-cpe-id` 前提，且 V1 从 2.76 改钉 2.77 未经赛题确认，答辩口径风险最大。
