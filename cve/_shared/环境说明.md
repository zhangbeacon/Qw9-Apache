# CVE 复现环境说明（三个子智能体共用）

## 1. 运行环境

- 宿主机：Windows，工作目录 `E:\强网拟态`（在 WSL 内是 `/mnt/e/强网拟态`）。
- 唯一 Linux 环境：**WSL1 发行版 `Ubuntu-CTF`**（Ubuntu 22.04.5，gcc 11.4.0，x86-64，root 用户）。
- 调用方式（PowerShell）：
  ```powershell
  wsl.exe -d Ubuntu-CTF -- bash /mnt/e/强网拟态/cve/<软件>/<脚本>.sh
  ```
  脚本请写成 `.sh`（**LF 换行、UTF-8**）放在 Windows 侧，避免 PowerShell 引号转义地狱。
- 常用工具已装：gcc/g++/make/autoconf/automake/libtool/pkg-config/perl/patch、
  gdb、tcpdump、nc、curl、wget、python3(+pip)、scapy（安装中）、
  libpcre2-dev、libapr1-dev、libaprutil1-dev、zlib1g-dev、libssl-dev、libexpat1-dev。

## 2. 网络

- WSL1 的 `/etc/resolv.conf` 里公网 DNS 不通，**每个新 shell 先执行**：
  ```bash
  bash /mnt/e/强网拟态/cve/_shared/netfix.sh
  ```
  之后 `curl` / `git clone` / `pip download` 可用（速度一般，几十 KB/s～几百 KB/s）。
- 源码包已由主控下载到 `E:\强网拟态\cve\_downloads\`（WSL 内 `/mnt/e/强网拟态/cve/_downloads/`），优先用本地包，不要重复下载。
- 如果 WSL 里下载失败，可在 Windows 侧用 `curl.exe -L -o` 下载后再复用。

## 3. 磁盘与编译位置（重要）

- `/mnt/e` 是 9p 文件系统，**编译极慢**。请把源码解压/编译到 WSL 原生盘：
  ```bash
  mkdir -p /root/work/<软件> && cd /root/work/<软件>
  tar xzf /mnt/e/强网拟态/cve/_downloads/<包名> 
  ```
- 构建产物、二进制、配置文件、PoC 脚本、证据日志，最后都要**复制回**
  `E:\强网拟态\cve\<软件>\`（WSL 内 `/mnt/e/强网拟态/cve/<软件>/`），保证队友在 Windows 上能直接看。

## 4. 端口分配（三个智能体并行，严禁抢占）

| 智能体 | 软件 | 分配端口 |
|---|---|---|
| A | nginx 1.13.2 | HTTP **8081**、伪造 DNS **8053/udp** |
| B | dnsmasq 2.76 | DNS **5353/udp+tcp**、DHCP 关闭 |
| C | Apache httpd 2.4.49 | HTTP **8082**、备用 8083 |

- 启动服务前先 `ss -ltnup | grep <端口>` 确认没被占用；用完 `pkill -f <自己的进程>` 清理。
- 不要 kill 别人的进程，不要动 `/root/work/` 下别的软件的目录。

## 5. 目录规范（每个软件一致）

```
E:\强网拟态\cve\<软件>\
├── README.md                 # 软件级总览：版本、CVE 清单、复现状态表
├── build\                    # 构建脚本（build.sh 可一键重跑）+ 编译日志
├── conf\                     # 复现所需配置（nginx.conf / dnsmasq.conf / httpd.conf 片段）
├── poc\<CVE>\                # 该 CVE 的触发脚本（python/shell），可带参数重跑
├── evidence\<CVE>\           # 原始证据：命令输出、服务日志、ASAN/backtrace、响应报文、core
└── report\<CVE>.md           # 单 CVE 复现报告（见模板）
```

## 6. 证据要求（硬性）

每个 CVE 至少留下：
1. **版本证据**：`<软件> -v` 或源码 `CHANGES`/`version.h` 输出，证明是钉住的漏洞版本；
2. **构建证据**：`configure` 参数、`make` 结尾日志、二进制 `sha256sum`、`file`/`ldd` 输出；
3. **漏洞存在证据**：对应源码片段（行号）+ 官方修复 commit/diff 链接（NVD/上游公告），说明修复前后差异；
4. **触发证据**：PoC 完整命令 + 原始输出 + 服务端日志/崩溃信号（SIGSEGV/SIGABRT/ASAN 报告）；
5. **判定条件**：机器可判定的成功标准（退出码、响应含特定字节、进程消失、core 文件、`dmesg` 段错误），写进脚本。

> 禁止编造输出。没跑通就如实写"未复现 + 卡点"，并换备用 CVE。

## 7. 单 CVE 报告模板（report/<CVE>.md）

```markdown
# <CVE> @ <软件> <版本>

## 1. 结论
- 复现状态：成功 / 部分成功 / 未复现（附一句话原因）
- 漏洞类型：CWE-xxx 名称
- 影响：信息泄露 / DoS / 内存破坏 / RCE（如实，不夸大）
- CVSS（NVD）：x.x

## 2. 版本与影响范围
- NVD 影响区间：<= x.y.z（修复版本 x.y.z）
- 本机钉住版本与来源（URL + sha256）

## 3. 根因
- 文件:行号，函数，错误逻辑
- 修复 diff（链接 + 关键 hunk）

## 4. 构建
- configure/make 命令、关键编译选项、产物 sha256

## 5. 复现步骤
1. 启动命令（配置见 conf/）
2. 触发命令（poc/<CVE>/...）
3. 预期输出

## 6. 实测证据
- 原始输出片段（贴 evidence/ 文件路径）
- 崩溃信号 / ASAN 摘要 / 泄露字节

## 7. 判定脚本
- `bash poc/<CVE>/verify.sh` → 退出码 0 表示命中

## 8. 与赛题的贴合度
- 攻击面（网络接口/外部输入）、自动化程度、在 V2/V3 变体上的预期差分
```

## 8. 工作纪律

- 每个 CVE 先跑通再写报告；报告里的每条结论都要能指到 `evidence/` 里的文件。
- 单 CVE 卡住超过约 60–90 分钟，记录卡点、切备用 CVE，不要死磕。
- 全部脚本必须能"从零重跑"：解压 → 构建 → 起服务 → 打 PoC → 判定。
- 结束时给主控回一份简短汇总：CVE 列表、成功/失败、证据路径、遗留问题。
